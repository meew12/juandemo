# 🚨 FIX RÁPIDO: Error 500 en cPanel (GoDaddy)

> **El error 500 significa que la app Node.js arrancó pero está crasheando.**
> Causa más común: subiste los archivos pero **NO ejecutaste `npm install` y `npm run build`**.

---

## 🩺 DIAGNÓSTICO: ¿Por qué crashea?

La app Node.js necesita 3 cosas que NO están en el ZIP:

| Lo que falta | Cómo generarlo | Tiempo |
|--------------|----------------|--------|
| ❌ `node_modules/` | `npm install` | 2-3 min |
| ❌ `.next/standalone/server.js` | `npm run build` | 3-5 min |
| ❌ `public/` y `.next/static/` copiados | manualmente | 30 seg |

Sin esos archivos, `app.js` no tiene nada que ejecutar → crashea → error 500.

---

## ✅ SOLUCIÓN: 5 pasos para arreglar el 500

### Paso 1 — Entrar al gestor de Node.js

1. cPanel → **Software → Setup Node.js App**
2. Al lado de tu app, click en **Edit** (lápiz)

### Paso 2 — Verificar que el `.env` existe

En la carpeta raíz de tu app (`/home/miusuario/umpi/`), debe existir un archivo llamado `.env` (con el punto inicial) con este contenido:

```env
DATABASE_URL="mysql://myjuanumpi56:123456789%24%24aN@localhost:3306/umpidata"
NEXTAUTH_SECRET="3WL0unwbzE9gHHHnqzyfmC+RqhSfuKzRE4IftsNThK8="
NEXTAUTH_URL="http://juanumpi.com.mialias.net"
MERCADOPAGO_ACCESS_TOKEN="TEST-umpi-placeholder-replace-with-real-test-token"
MERCADOPAGO_PUBLIC_KEY="TEST-umpi-placeholder-pk"
NODE_ENV="production"
```

Si no existe, crealo con **File Manager → New File → .env** y pegá ese contenido.

### Paso 3 — Verificar que `schema.prisma` use MySQL

En `prisma/schema.prisma`, la primera línea del `datasource` debe decir:

```prisma
datasource db {
  provider = "mysql"   ← debe decir mysql, NO sqlite
  url = env("DATABASE_URL")
}
```

Si dice `sqlite`, hacé esto desde File Manager:
- Borrá `prisma/schema.prisma`
- Renombrá `prisma/schema.mysql.prisma` → `schema.prisma`

### Paso 4 — Ejecutar npm install y build (EL PASO CRÍTICO)

En la interfaz de **"Setup Node.js App" → Edit**:

1. Buscá la sección **"Run NPM Install"**
2. Click en el botón **"Run NPM Install"**
3. Esperá a que termine (2-3 minutos). Vas a ver un log.
4. Cuando termine, en el campo **"Run script"** (debajo), escribí: `build`
5. Click en **"Run script"** → ejecuta `npm run build`
6. Esperá 3-5 minutos hasta que veas "Compiled successfully"

### Paso 5 — Copiar el build standalone a la raíz

Después del build, los archivos que Next.js necesita para arrancar están en `.next/standalone/`. Hay que copiarlos al lado de `app.js`.

#### Si tenés acceso SSH:
```bash
cd ~/umpi
cp -r .next/standalone/. .
cp -r .next/static .next/
ls -la server.js   # debe existir ahora
```

#### Si NO tenés SSH (solo File Manager):
1. Andá a `.next/standalone/` en File Manager
2. Seleccioná **TODOS** los archivos ahí (server.js, package.json, carpeta node_modules, etc.)
3. Click **Move** → movelos a la raíz de tu app (`/home/miusuario/umpi/`)
4. Confirmá sobreescribir si pregunta

> ⚠️ Asegurate de que `server.js` quede en `/home/miusuario/umpi/server.js` (NO en una subcarpeta).

### Paso 6 — Restart y verificar

1. En **Setup Node.js App**, click en **Restart** (ícono circular ↻)
2. Esperá 10 segundos
3. Abrí http://juanumpi.com.mialias.net

## 🔍 Si sigue dando error 500

Mirá los logs para ver el error específico:

1. **Setup Node.js App → Edit** → click en **"View logs"** (botón con ícono de documento)
2. O abrí con File Manager: `/home/miusuario/umpi/logs/umpi.log`
3. Andá al **final del archivo** y buscá el último error

### Errores comunes y su solución:

| Error en log | Causa | Solución |
|--------------|-------|----------|
| `Cannot find module 'next'` | No corriste `npm install` | Paso 4 |
| `Cannot find module '.prisma/client'` | No corriste `prisma generate` | Ejecutá `npx prisma generate` |
| `Cannot find module './server.js'` | No copiaste `.next/standalone/*` | Paso 5 |
| `ECONNREFUSED 127.0.0.1:3306` | MySQL no accesible | Verificá credenciales en `.env` |
| `JWEDecryptionFailed` | Falta NEXTAUTH_SECRET | Paso 2 |
| `PrismaClientInitializationError` | Schema.prisma sigue en sqlite | Paso 3 |
| `getaddrinfo ENOTFOUND localhost` | Variable HOSTNAME mal seteada | Borrala de cPanel → Environment variables |
| `Error: connect ETIMEDOUT` | BD no responde | En cPanel → Remote MySQL, agregá `localhost` |

## 🆘 Si nada funciona: alternativa Vercel

Si después de todo seguís con problemas, **Vercel** es mucho más simple para Next.js (es del mismo creador):

1. Subí el código a un repo de GitHub
2. En https://vercel.com → New Project → importá el repo
3. En **Environment Variables** agregá las 6 variables del `.env` (con `localhost` reemplazado por la IP pública de tu MySQL de GoDaddy)
4. En cPanel → **Remote MySQL** → agregá `%` (permitir conexiones remotas)
5. Deploy → listo en 3 minutos

Vercel detecta Next.js automáticamente, compila y despliega sin que tengas que hacer nada manual.
